MOBILE AUDIO DIAGNOSTIC

Test procedure

  1. Turn the phone's media volume up.
  2. Leave the Ring/Silent setting where it is now for the first pass.
  3. Press tests 1 to 5, one at a time, and listen after each.
  4. After every test press HEARD IT or DID NOT HEAR IT.
  5. Press COPY RESULTS and send them back.
  6. If this phone has a Ring/Silent switch or a silent/vibrate mode, reload the page and repeat the whole run with that setting flipped. Not every phone has one.

Nothing plays until you press a button. Every test plays the same 660 Hz beep, about 0.4 seconds.

Device / runtime

1. Web Audio — play now

Oscillator created and started synchronously inside the tap. No timer, no promise, no animation frame before start(). Tests whether Web Audio can make sound at all on this device.

NOT TESTED

2. Web Audio — play after 2 seconds

Context resumed from the real tap, but the oscillator starts 2 seconds later, outside the gesture. Compares trusted-gesture Web Audio with later programmatic use.

NOT TESTED
-

3. DOM <audio> — play now

One real <audio playsinline preload="auto"> element that is in the page markup. play() is called directly in the tap. No pool.

NOT TESTED
-

4. Same DOM <audio> — replay after 2 seconds

The exact same element as test 3. Plays once from the tap (result A), then 2 seconds later rewinds and plays again programmatically (result B). This is the pattern the game uses for a catch sound, and it is the critical test.

NOT TESTED
-

5. Detached new Audio() — play now

One new Audio(...) that is never added to the page. play() called directly in the tap. Isolates DOM element vs detached element.
